# fixed_path 停车效率实验

本目录用于隔离 Gazebo 筛选与验收，不会自动覆盖生产 YAML、提交或推送。

## 判定标准

- 请求速度为 0.1～1.5 m/s、间隔 0.1；实际速度须在请求值 ±5% 内连续保持至少 0.5 秒，否则该请求档不通过。
- Action 须成功；停稳后完整 1 秒窗口内 map 定位 XY 最大误差 ≤10 mm、线速度 ≤0.01 m/s、角速度 ≤0.05 rad/s，TF 新鲜且采样无超过 0.1 秒的缺口。窗口内位置漂移另报，不附加未经用户选择的 3 mm 阈值。
- Collision Monitor 保持启用。仅在自己的 ROS Domain 和 Ignition partition 内启动、复位、发送任务；复位不重置仿真时间。复位使用明确的实验初始位姿，不在运动中注入位姿。
- Gazebo 真值仅旁路记录，不作为定位或控制输入。map 精度通过不代表物理 10 mm 精度。
- 基线和候选使用同一通道、请求速度、几何起终点、碰撞配置及定位配置；改变定位配置或精度条件后，必须建立新基线。

## 单组运行

在 nav2_ws 完成必要包定向构建并加载环境后运行：

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
python3 src/navigation2/nav2_regulated_modules/tools/run_speed_case.py \
  --output /tmp/fixed-path-stop-example \
  --speed 0.1 --length 2 --repeats 5 --direction both \
  --stationary-seconds 10 --goal-timeout 180
```

默认实验通道为原仓库地图中的 x=-3.5、起点 y=-7.3、车头朝 +Y。前进从底端到顶端，后退从顶端到底端；每次 Goal 前复位机器人与 AMCL 初始位姿，等待停稳。测试前仍须核对所选地图／场景的通道及保护区可通行性。

`--params-file` 可指定隔离仿真定位配置；`--margin`、`--creep`、`--deceleration`、`--tolerance` 和 `--terminal-lookahead` 为实验参数。原 YAML 不修改。内部停车容差与外部 10 mm 验收分别记录；更严格的内部容差不得代替完整停后观察。

正式实验保持 `--tolerance 0.01` 为成功判定半径，并使用 `--stop-entry 0.005` 预留停车空间。
该选项写入 `FixedPathController.goal_stop_entry_tolerance`；插件默认 0.0 保留原逻辑，显式启用后
停车入口与验收半径分离，并逐周期复核当前位置准确性。越过终点平面仍停车，精度超出 10 mm 时仍拒绝成功。
5 mm 入口不能代替 10 mm 停后窗口，不增加默认终点旋转、反向补偿或生产连续等待。

`--map-file` 选择由未改场景可见几何生成并经真实激光残差检查的实验地图；不改变扫描输入。
`--seed` 指定 AMCL 启动随机种子（默认实验值 3407），正式对应批次采用同种子，第二批采用 3408。
官方 main 借鉴、兼容范围和种子行为见 [AMCL 核对记录](./UPSTREAM_AMCL.md)。

接近目标后零速度保持 3 秒而 Action 未完成时，**测试工具**取消任务并确认停车；这是测试保护，不修改生产终点超时或恢复语义。任何 Action／精度／达速失败即停止本组，不把失败后的新路径接续当成原矩阵。

## 证据

每组保留 results.json、实际参数、实验世界／参数副本、启动日志、每次停后窗口及压缩原始速度／TF／定位／路径／真值／扫描。末端测量区间统一为 max(0.8 m, v²/(2×0.25)+0.1v+0.1 m)，耗时包含完整停稳观察。

速度和位姿连续采集；扫描旁路默认每秒保存一帧全束数据（`--scan-every` 可调整），不降低实际扫描频率。
采集端若因调度暂停读到旧消息，会先等待新里程计，并记录恢复事件；仍无新数据或停后窗口有缺口时不通过。

正式对照每个速度、方向各 10 次，基线和候选交替批次运行；只有候选 10/10 达标、同档末端耗时 P95 降低至少 20%、整程耗时与成功率不退化，才标记“明显改善”。失败或未执行档位须明确列出，不能推广整段速度。
